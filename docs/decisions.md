# Decisions

Append-only. A later entry that replaces an earlier one says so.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-10-29 | The position is an absolute rectangle (dp from the screen's top-left), pushed to the native window on every change and rotation. | The plugin stores a centre-relative offset that Android reinterprets when the screen dimensions swap; transposing it after the fact (accelerometer, 250 ms late, rounded) made the overlay jump. |
| 2 | 2026-10-29 | After rotation the shape keeps the same screen pixels and size. **Replaced by #16.** | Chosen by the user. |
| 3 | 2026-10-29 | Native `ScreenSizeBridge` pushes the real screen size and the parent-frame centre shift to the overlay engine. | Measured on an API 36 emulator: `didChangeMetrics` fires in the overlay engine but `Display.size` stays at its first value; the plugin centres its window in a frame that excludes the navigation bar. |
| 4 | 2026-10-29 | A shape that no longer fits after rotation is shown clamped; the stored rectangle is untouched. **Obsolete after #16**: a glass-pinned shape always fits. | A shape placed low in portrait would be off-screen in the shorter landscape screen; rotating back must restore it exactly. |
| 5 | 2026-10-29 | No full-screen `match_parent` overlay window. | A Flutter view cannot pass touches through transparent areas, so the camera app underneath would stop receiving touches. |
| 6 | 2026-10-29 | Three slots, managed on the home screen only; each stores the screen it was saved on. | Chosen by the user; the screen size lets the thumbnail draw the right phone and loading in another orientation clamp. |
| 7 | 2026-10-29 | `ChangeNotifier` + `ListenableBuilder`, no `provider`. | Two small view models; a dependency is not worth it. |
| 8 | 2026-10-29 | Gradle 9.1.0 / AGP 8.13.0. | Android Studio's JDK is 25, which Gradle 8.14 does not support. |
| 9 | 2026-10-29 | The overlay window is not tested on iOS. | `flutter_overlay_window` is Android-only; only the shared Dart logic and UI could run there, and the project has no `ios/` folder yet. |
| 10 | 2026-10-29 | `main.dart` holds only the entry points; platform access from the main app goes through `OverlayHost`, and `Dependencies` is the single wiring point. | The 448-line `main.dart` mixed UI, permission, port and channel code that could only be tested by mocking platform channels. |
| 11 | 2026-10-29 | The `portName` handshake (500 ms delay + `shareData`) is removed. | Both sides use the constant `overlayPortName`; the handshake only delayed startup. |
| 12 | 2026-10-29 | Slot save/load is covered by unit tests on one repository, plus a single device script (`tool/slots_e2e.sh`). | The logic is in Dart; the script only proves the real window ends up on the saved frame. |
| 13 | 2026-10-29 | The project has an `ios/` folder (replaces the iOS part of #9). | Requested by the user to run the shared Dart logic and UI on the iOS simulator; the overlay window is still Android-only. |
| 14 | 2026-10-29 | Stay on `flutter_overlay_window` 0.5.0 (tried 1.0.2). | 1.0.2's native service constrains window positions to the screen and handles x/y differently: `tool/rotation_e2e.sh` and `tool/slots_e2e.sh` both failed with it (overlay jumped after rotating, slot 1 did not restore). Revisit only with a rewritten `toPluginOffset` and the scripts as the check. |
| 15 | 2026-10-29 | Stay on the legacy Kotlin plugin (`android.builtInKotlin=false`, `android.newDsl=false`) although Flutter 3.47.9 warns about it. | Latest stable Flutter's Gradle plugin still rejects AGP 9's new DSL, which built-in Kotlin requires. |
| 16 | 2026-10-29 | The overlay is pinned to the phone's glass: stored in natural-orientation coordinates, drawn rotated by the display rotation, panel always upright. Replaces #2. Slots are glass coordinates (#6 no longer clamps between orientations). | The user tried the screen-pixel behaviour on a phone and wanted the shape to keep its exact position and shape relative to the physical glass and borders. Needs the display rotation, so the native bridge reports it. |
| 17 | 2026-10-29 | The native window is exactly the shape; handles and panel are drawn inside it (panel beside the shape only when the shape is too small). Max size is the screen, not 500dp. | The old window added a 20dp margin and a 60dp panel around the shape, so the shape could not reach the screen edge and the panel left the screen near the right side. |
| 18 | 2026-10-29 | `tool/rotation_e2e.sh` draws a tall rectangle and samples the screenshot for the gold border on all four edges. | A frame-only check passed while the Flutter view still drew the old shape (the view model did not notify on rotation); sampling pixels fails on that bug. |
| 19 | 2026-10-29 | The main app sends `open` to the overlay after every start; the view model `reopen()`s. | The plugin caches the overlay engine, so after Stop the Dart state (a closed view model) survives and a new window got no `initState`: the overlay came back frozen in a corner. Found by the user; reproduced by `tool/restart_e2e.sh`, which fails without the fix. |
| 20 | 2026-10-29 | Border size is a 1-20 dp slider and colour one of 7 swatches (no colour picker package); the style is global, not per slot, and saved in `PositionRepository`. | Requested on the home screen; a fixed palette covers dark and bright scenes without a dependency, and a slot is a position, not a look. |
